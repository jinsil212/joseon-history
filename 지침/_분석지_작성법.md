# 분석지 작성법

벤치마크 영상 한 편을 **11칸 분석지**로 만드는 방법. 창이 바뀌어도 같은 형식이 나오게 하려고 적는다.
> 2026-09-14 미드폼 이관판. 이 파일은 새 분석의 수집·기록 양식이다. 제작 규칙은 현행 `_대본지침서.md` 한 곳을 따른다. 견본의 옛 판정은 현재 합격 기준이 아니며 사용처와 마지막 이관 주석을 확인한다.

**견본은 `따뜻한심리학/분석지/003_미니멀라이프/분석지.md`다. 쓰기 전에 반드시 통째로 읽는다.**

## 0. 이 분석지가 왜 필요한가

새 주제를 받았을 때 **잘 된 영상의 기획·썸네일·제목·도입부·원고 전개의 기능을 확인하고 새 주제의 검증 사실에 적용**하려고 만든다.
그래서 분석지는 **감상문이 아니라 관찰과 적용 가능성을 대조하는 자료**다. 현행 공용 P0-8·0-3에 따라 원본의 수량·비율·물증·반전을 의무로 올리지 않는다. 판정 기준 하나:

> **"새 주제를 받았을 때 원고를 쓰면서 이 칸을 실제로 열어보게 되는가?"**

열어보지 않을 칸은 넣지 않는다.

## 절대 규칙 여섯

1. **원문을 처음부터 끝까지 읽는다.** 훅과 클로징만 읽고 중간을 모르면 분석지가 전부 겉핥기가 된다
2. **원문 인용은 요약 금지.** 도입부·전환 문장·클로징은 자막 그대로 옮긴다. 어미·호칭·끊어치기가 자산이다
3. **시계로 자르지 않는다.** 도입부가 어디서 끝나는지는 뜻으로 판정하고, 판정 근거 문장을 적는다. 분석지 본문에 시각(00:00)은 쓰지 않는다
4. **문장 수·블록 수를 미리 정하지 않는다.** 도입부가 4문장일 수도 30문장일 수도 있다
5. **이 영상이 무엇을 어떻게 했는지만 적는다.** 파일 경로 안내, 주의사항, 채널 규칙과의 충돌 같은 건 넣지 않는다. 맨 마지막 표만 예외
6. **`## ` 섹션은 정확히 12개다. 1~11번 + 「이 영상이 지침서를 어기는 곳」.** 좋아 보인다고 「정리」·「우선순위」·「요약」 같은 섹션을 더 붙이지 않는다. 더 넣고 싶은 말은 이미 11칸 어딘가에 자리가 있다 — 거기 넣는다. 다 쓰고 나서 아래 명령으로 12가 나오는지 세어 본다

```bash
grep -c "^## " {채널}/분석지/NNN_이름/분석지.md    # 반드시 12
```

## 1. 원자재 수집

먼저 Python 실행 경로와 `yt_dlp` 설치를 확인한다. PATH의 `python`이 없으면 PowerShell에서 `_도구/python.ps1`을 사용할 수 있다. Python이 실행된다는 것과 수집 모듈이 설치됐다는 것은 별개다. 아래 명령의 `python`은 확인된 실행기로 대체한다.

```bash
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 python -m yt_dlp --skip-download --no-warnings \
  --write-auto-subs --write-subs --sub-langs "ko.*" --sub-format vtt \
  --write-info-json --write-comments \
  --extractor-args "youtube:comment_sort=top;max_comments=all,20,0,0" \
  --write-thumbnail --convert-thumbnails webp \
  -o "{임시폴더}/%(id)s.%(ext)s" "URL"
```

**함정 셋**
| | |
|---|---|
| `--print`를 같이 쓰면 저장이 전부 꺼진다 | 메타는 `info.json`에서 읽는다 |
| `en` 자막이 429로 실패하면 명령 전체가 죽는다 | `ko.*`만 요청. 한국어 자막이 없으면 `en`만 따로 |
| 콘솔이 cp949라 한글이 깨진다 | 제목·채널명은 python으로 `info.json`을 읽어 UTF-8 파일에 쓴다. 터미널 출력을 믿지 않는다 |

만들 파일 (`{채널}/분석지/NNN_한글이름/`)

| 파일 | 내용 |
|---|---|
| `원문.txt` | 자막을 평문으로 이어 붙인 것 |
| `원문_시점.txt` | `[hh:mm:ss] 문장` — 구간 판정용. 분석지에는 시각을 안 쓰지만 이건 남긴다 |
| `정보.md` | 제목 · URL · 채널명 · 구독자수 · 조회수 · 업로드일 · 길이 · 좋아요 · 수집일과 경과일 · 썸네일 · **댓글 TOP 10 표** |
| `썸네일.webp` 또는 `.jpg` | |

**자막이 15바이트면 수집 실패다.** 다시 받는다.

## 2. 정독하고 구간을 판정한다

1. `원문_시점.txt`를 처음부터 끝까지 읽는다
2. **도입부 끝** — `_대본지침서.md` 0-3·0-8·P0-8·H4·G3에 따라 클릭 질문을 키우는 구간이 끝나고 본격적인 답·증명이 시작되는 문장으로 판정한다.
   - 선언·첫 사례·진입 신호어는 후보를 찾는 단서다. **가장 늦은 것을 자동 채택하지 않는다.** 번호 목록보다 앞에 원인·정의·논증이 시작됐다면 그것도 본문이다.
   - 끝 문장과 바로 다음 문장을 원문 그대로 나란히 적고 각각의 기능과 판정 이유를 쓴다. 모호하면 두 후보를 비교한다. 선언 뒤의 모든 설명을 도입으로 밀어 넣지 않는다.
   - 경계를 바꾸면 3번 뼈대·4번 위치 해석·5번 전문과 지문·8번 전환·구간 계측·마지막 판정표를 함께 맞춘다. 재검토가 끝나지 않은 옛 판단은 사용 보류로 표시한다.
3. **클로징 시작** — 진입 신호 문장("진짜 반전은 지금부터입니다" 류) 또는 마지막 요약이 시작되는 문장
4. 계측을 돌린다
   ```bash
   python _도구/bench-metrics.py 원문.txt --minutes {분+초/60의_계산값} \
     --hook-end "{도입부 끝 문장 일부}" --closing-start "{클로징 첫 문장 일부}"
   ```
5. **썸네일을 실제로 연다.** 안 보고 적지 않는다

**누락과 판정의 범위:** 저장 자막이 끝 문장 중간에서 끊겼으면 `정보.md`와 10번 칸에 그 상태를 남긴다. 괄호로 끝말을 만들어 인용하거나 CTA가 없다고 단정하지 않는다. 확보 원문 정독·원영상 확인·연구 팩트 확인은 서로 다른 완료 상태다. 자동자막 교정은 원발화 확인 전까지 추정이며, 원문 파일은 보존한다.

**현재 규칙 적용:** 견본의 옛 번호를 복사하지 말고 P·T·H·B·S·G의 해당 내용을 찾아 적용한다. 원본 관찰과 우리 채널에서의 채택 여부를 구분한다. 마지막 표에서는 관찰 사실 / 현재 기준 / 적용·비적용 이유를 적는다. 인물 없음·물증 3개 미달·번호 요약만으로 모든 분야의 실패를 판정하지 않는다(0-3·0-8·P0-8·H4·G3). 성공 원인은 유지율 등 직접 근거 없이 확정하지 않는다.

## 4. 색인에 한 줄 등록

`{채널}/분석지/_색인.md` 결정표에 행 하나. 이 표만 읽어도 어느 분석지를 쓸지 고를 수 있어야 한다.

| 칸 | 어디서 뽑나 |
|---|---|
| 한 줄 질문 | 이 영상은 "왜 ___인가"에 답한다 — 1·3번에서 |
| 후반이 하는 일 | 후반이 무엇을 뒤집고 어디에 착지하나 — 3·4·10번에서 |
| **필수 재료 3~4개** | 4번 순서 원리와 11번에서 역산 — **이 구조가 굴러가려면 주제가 반드시 가져야 하는 것**. 없으면 생기는 일도 함께 |
| 안 맞는 것 → 대신 | 재료의 반대 |
| 실적 | 조회수 ÷ 구독자 = 배수 · 일평균 · 좋아요율 |
| 근거 | 처음엔 `1편 관찰`. 같은 질문에 답하는 분석지가 하나 더 생기면 두 개를 대조해 **색인 행만** `확인 n=2`로 올린다. 분석지는 안 건드린다 |
| 사용 이력 | 이 구조로 쓴 우리 편. 처음엔 `—` |

## 6. 하지 말 것

- 원문을 요약해서 인용하기
- 시계로 도입부 자르기 (0~30초 같은 식)
- 분석지에 파일 경로·주의사항·읽는 법 적기
- 채널 규칙과의 충돌을 분석지 본문에 적기 (맨 마지막 표에만)
- 발췌만 읽고 쓰기
- 규칙 번호나 만들어낸 용어 쓰기 — **쉬운 말로 적는다**
- **12칸 밖에 섹션 더 붙이기** — 「반드시 가져올 것」, 「핵심 요약」, 「우선순위」 전부 금지. 견본(001)에 없으면 넣지 않는다
